# 南药智耕 · 南药智慧种植平台

React + NestJS + Prisma + MySQL 的本地全栈课程设计。业务数据持久化到 MySQL，前端不使用本地假接口。初始业务记录和环境采样为**明确标注的课程模拟数据**，不接入真实传感器，不提供生产决策或药材安全认证。

## 启动与登录

项目路径：`C:\Users\Administrator\Desktop\学习\课设`

本机已配置 MySQL 8.4，可直接双击根目录的 **`启动平台.cmd`**。启动完成后打开：

- 前端：<http://127.0.0.1:5173>
- API：`http://127.0.0.1:3000/api`
- 本项目 MySQL：`127.0.0.1:3307`，数据库 `nanyao`
- 演示账号：管理员 `admin`，种植人员 `farmer`
- 随机生成的初始密码：查看 **`.local/演示账号.txt`**

启动窗口需要保持打开。不要在已经运行时重复启动。关闭窗口或按 `Ctrl+C` 停止前后端；`npm run db:stop` 安全停止本项目数据库，保留数据。

### 首次手动启动

需要 Node.js 22.12+、npm 和 MySQL 8.4。以下命令在项目根目录执行，PowerShell 中可用 `npm.cmd` 代替 `npm`：

```powershell
npm.cmd ci
npm.cmd run setup
npm.cmd run dev
```

`setup` 按顺序启动独立 MySQL、生成 Prisma Client、应用迁移、填充演示数据。后端与前端均支持开发热更新。

### 数据位置和安全边界

- 源码：`apps/web`、`apps/api`、`prisma`、`scripts`、`tests`。
- MySQL 数据文件：`.local/mysql`。脚本使用相对数据路径，兼容当前中文目录。
- 数据库连接、JWT 密钥、初始演示密码：根目录 `.env`。
- 独立数据库管理信息：`.local/database.json`。
- `.env` 和 `.local` 已加入 `.gitignore`，不要上传、公开或提交。
- 脚本使用本机 MySQL 可执行程序，**不修改已有 MySQL84 服务、不使用 3306、不读取已有数据库**。
- API、前端和独立 MySQL 仅绑定 `127.0.0.1`。此交付不包含互联网部署。

如果 MySQL 安装位置不同，可先设置：

```powershell
$env:MYSQL_BIN = 'D:\MySQL\bin\mysqld.exe'
npm.cmd run setup
```

若使用自行管理的 MySQL：复制 `.env.example` 为 `.env`，填入真实连接、至少 32 字符的随机 JWT 密钥和至少 8 字符的演示密码，然后运行：

```powershell
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run db:seed
npm.cmd run dev
```

自行管理的数据库不运行 `db:local` 或 `启动平台.cmd`。迁移前核对目标数据库，应使用本项目专用空库。

## 功能与权限

| 模块 | 已实现功能 |
|---|---|
| 登录权限 | 密码散列、8 小时 JWT、管理员与种植人员、过期重新登录 |
| 基地总览 | 面积、在种批次、待办/逾期农事、采收统计、趋势图、品种分布 |
| 南药档案 | 新增、编辑、搜索、详情、删除；品种阈值用于预警判断 |
| 种植管理 | 地块与种植批次管理、日期校验、在种/已采收状态、关联删除保护 |
| 环境监测 | 按地块查看最近 24 条历史采样；常规/干旱/高温模拟采样 |
| 预警处理 | 温度/土壤湿度阈值判断、未处理预警去重、人工处理记录 |
| 农事管理 | 创建与分配任务、类型/负责人/状态筛选、结果登记、逾期提示 |
| 采收溯源 | 整批采收、唯一溯源码、农事时间线、采样数量、内部查询二维码 |

管理员可维护南药/地块/种植批次、安排农事、生成模拟采样。种植人员可读取业务数据、完成**本人被分配**的农事、登记预警处理及采收。管理员也可完成农事。权限在后端执行，不只隐藏前端按钮。

### 业务规则

1. 种植日期不能在未来，预计采收不能早于种植。
2. 温度和湿度下限必须小于上限，数字字段限制合理输入范围。
3. 有关联业务记录的档案、地块、批次不能删除。
4. 批次已有农事或预警记录后，不再允许编辑原始关联；采收后不可追加农事。
5. 农事完成必须填写结果，不能重复完成。预警处理必须填写处理记录，不能重复处理。
6. 采收前必须完成该批次所有待办，采收时间不得早于最后一次农事完成时间。一次采收代表**整批结束**，暂不支持分批采收。
7. 采收记录与批次状态在一个事务中更新，重复或并发采收不能产生两条记录。
8. 已处理预警不代表环境恢复正常，后续异常采样仍可再次生成预警。
9. 溯源需登录，二维码是内部页面地址，不是面向公众的认证证书。地块信息、品种档案是当前维护值，系统不宣称防篡改或第三方认证。

## 初始数据

6 种南药：广藿香、砂仁、巴戟天、益智、穿心莲、五指毛桃。

5 个地块、4 个在种批次、1 个已采收批次、6 条农事、120 条模拟采样、2 条待处理预警。初始采收溯源码：`NY-DEMO-CXL-001`。

`db:seed` 可重复执行，按示例名称/编号补充缺失记录，不重置已有记录或账号密码。演示日期在首次初始化时相对当前日期生成，之后不会自动刷新。

## 建议验收顺序

1. 用 `admin` 登录，查看总览图表和统计，刷新后数据仍来自数据库。
2. 在“南药档案”搜索“广藿香”，打开详情；尝试删除已有批次的品种，应提示关联保护。
3. 新增一个地块，再建立一个新种植批次，选定南药、日期和数量。
4. 在“农事管理”为新批次安排一项农事，执行人选择 `farmer`。
5. 在“环境监测”选择新地块，生成“干旱场景”采样，查看预警；重复采样不重复增加同一未处理指标的预警。
6. 切换 `farmer`，确认不能维护档案、安排农事或生成采样，但能填写结果并完成自己的任务。
7. 登记该批次采收，确认其状态变为“已采收”，生成新的溯源码。
8. 打开溯源档案，核对地块、品种、农事、采收重量与去向。
9. 在窄屏或手机模拟器中检查侧边导航、表单、列表和图表。

也可直接查询 `NY-DEMO-CXL-001`，快速查看完整示例履历。
